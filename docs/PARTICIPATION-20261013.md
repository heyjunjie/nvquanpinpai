# 关注更新、补证任务与内容效果

本次延续浅色报刊式档案布局。品牌目录仍在首页前部，访客与贡献统计在桌面侧栏、手机阅读内容之后。

## 读者入口

- 首页品牌旁的书签与品牌弹层的关注按钮共用一份浏览器关注清单。新增关注时，以目前的公开更新作为已读基线；此后新增公开资料或结构化更正显示为未读。打开具体记录标为已读，也可全部标为已读。
- 关注和已读保存在当前浏览器，不同步到账户；清除本地数据会移除关注，首页永久累计访客不受影响。旧版关注清单可继续使用，缺少已读历史时会显示现存未读记录。
- `/feed.xml?brand=品牌名` 为单品牌 RSS，使用 URL 编码；未知或未公开品牌返回 404。订阅器可用于跨设备跟踪。未发送邮件，也未申请浏览器推送权限。
- `/tasks` 为可独立访问、可收录的补证任务页，首页展示前三项待补任务，事件详情内显示关联任务。任务要求包括原始材料、日期依据、发布主体、回应原件。
- 投稿链接使用 `/reply/事件ID?task=任务ID`，在原有表单中保留任务与事件。可以不注册，必须留名。图片与视频限制、私有待审附件、内容审核流程沿用原有实现。

## 任务与贡献

首批 13 项仅整理现有公开档案的资料缺口，来源见 `evidence-tasks-20261013.json` 的事件 ID。没有新增品牌事实指控，没有把转载日期推定为原始发布日期。五项日期任务仅在相关事件日期仍为空时初始化。

管理员在 `/admin` 创建任务、审核投稿，并从已公开的关联回应／补充记录中选择完成依据，填写至少 10 字的核对说明后标为补齐。没有公开依据不能完成任务。也可以重新开放、归档任务。

公开任务只显示当前已公开的关联贡献和署名，不泄露待审条目 ID、标题、数量或附件。归档任务、关联事件未公开的任务不进入公开列表。完成依据被撤回后，公开任务自动显示待补，撤回的署名与说明不继续作为完成依据展示。补齐某项材料不自动升级整个事件的事实核实状态。

## 统计口径

首页原有永久累计访客与贡献排行保留。新报告仅管理员可见，展示上海时区最近 30 天的数据：

| 指标 | 口径 |
| --- | --- |
| 查看 | 实际访问公开页面的去重访客估算；同页期间内多渠道去重 |
| 分享点击 | 点击事件摘要分享或图片分享的去重访客；不声称外站发布成功 |
| 下载点击 | 点击资料卡下载的去重访客；不声称设备保存成功 |
| 打开投稿 | 打开投稿表单的去重访客；关联投稿归到原事件 |
| 收到投稿 | 服务器成功保存的条数，按投稿当时的页面关联 |
| 已公开 | 上述投稿中目前审核状态为公开的条数，撤回后减少 |
| 回访 | 最近 30 天访问过，并且有更早日访问记录的去重访客 |
| 入口与来源 | 每位访客每日、每渠道首个页面，展示期间去重人数；各行不可相加 |

客户端只传允许列表内的渠道名称和站内页面路径。服务器再次校验当前公开页面，删除查询参数；不存储原始 IP、完整引荐网址或搜索词。沿用已有 HMAC 访客标识，网络或浏览器特征变化可能影响估算。管理员和已识别爬虫不纳入新内容统计，操作接口限制频率并沿用来源及登录 CSRF 检查。

新内容指标从部署时开始记录，不伪造或回填历史数据；回访可利用已有来源访问记录。统计是观察实际效果的工具，不保证流量增长，也没有替用户发布到外部社交账户。

## 数据与发布边界

新增 `evidence_tasks`、`evidence_task_links`、`content_activity`、`content_landings`、`submission_attribution`、`growth_meta` 六张表。任务种子按固定 ID 幂等插入，现有任务不会被覆盖。既有反馈、日期、证据、账号、密钥和访客历史不重写。

部署沿用 `deploy/release.sh`：新镜像通过类型检查与测试后，仅切换 `brand-watch` 容器；切换前保留完整数据备份与旧容器。不得以本地验收数据库覆盖生产数据库。两个原主站容器、Caddy 配置和域名路由保持原配置。

## 验证

`npm run typecheck` 与 `npm test` 包含真实 HTTP 审核流程、任务权限、CSRF、待审隐私、完成依据限制、撤回重新待补、单品牌 RSS、公开任务转义、统计去重、回访与未读状态测试。

浏览器隔离验收实际走通关注后更新提醒、打开即已读、游客图片与视频投稿、管理员附件预览、3 秒视频播放到结尾、审核与任务完成、公开署名、PNG 下载及服务器下载计数。桌面 1280、手机 390 和窄屏 320 像素检查；后台六项指标在手机分三列两行显示，保留可读数字。所有验收投稿只存在于本地隔离数据目录。
